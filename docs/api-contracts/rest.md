# REST Contract

Initial public REST surface:

- `GET /health`
- `POST /auth/login`
- `POST /auth/refresh`
- `POST /auth/logout`
- `GET /auth/me`
- `GET /admin/users`
- `POST /admin/users`
- `PATCH /admin/users/:id`
- `PATCH /admin/users/:id/permissions`
- `GET /admin/bans`
- `POST /admin/bans`
- `DELETE /admin/bans/:id`
- `GET /admin/conversations`
- `GET /admin/messages`
- `PATCH /admin/messages/:id`
- `DELETE /admin/messages/:id`
- `GET /user/conversations`
- `GET /user/messages`
- `POST /user/messages`
- `POST /attachments/upload-intent`
- `GET /attachments/:id/signed-url`
- `POST /voice/token`
- `GET /notifications/vapid-public-key`
- `POST /notifications/subscriptions`
- `DELETE /notifications/subscriptions/:id`
- `GET /admin/geoip/:ip`

Important request shapes:

- `PATCH /admin/users/:id` accepts `status` and/or `role`.
- `POST /user/messages` accepts `conversationId`, `body`, and optional `attachmentIds`.
- `POST /attachments/upload-intent` returns top-level `id`, `uploadUrl`, `fileName`, `contentType`, `byteSize`, plus `attachment` and `cacheControl: no-store`.
- `POST /notifications/subscriptions` accepts `provider` (`web-push`, `fcm`, or `apns`), `endpoint`, optional Web Push `keys`, `platform`, and `deviceId`. Notification payloads include message and conversation IDs, not message body text.

OpenAPI is generated by the NestJS app at `/openapi`; raw JSON is available at `/openapi-json`.
